# MCP server support

pk can load explicitly configured Model Context Protocol servers over stdio or remote Streamable HTTP. It uses the official [MCP Go SDK](https://github.com/modelcontextprotocol/go-sdk) for initialization, tool discovery, calls, protocol framing, cancellation, and shutdown.

Configure stdio servers with `pk mcp add --id files --command /absolute/path/to/server [--arg ARG] [--env KEY=VALUE] [--cwd /absolute/path]`. Configure remote Streamable HTTP endpoints with `pk mcp add --id cloudflare-docs --url https://docs.mcp.cloudflare.com/mcp`. For static auth, use `--auth bearer-env --bearer-env TOKEN_ENV` or `--auth header-env --header X-API-Key --header-env KEY_ENV`; token values stay in the environment and are not accepted as command-line arguments. The TUI can store a bearer/API-key value separately in `~/.pk/mcp-secrets.json` with mode `0600`; the server config stores only a random reference. `pk mcp list` shows safe endpoint/auth metadata and never credential values. Adding or removing a server only changes configuration. Servers start/connect when a new CLI run loads the list, and a live session's saved tool set remains fixed. Resuming a session requires the same MCP configuration and discovered schemas as when it was created.

Cloudflare's [official MCP server catalog](https://developers.cloudflare.com/agents/model-context-protocol/cloudflare/servers-for-cloudflare/) lists the account server `https://mcp.cloudflare.com/mcp` and the public documentation server `https://docs.mcp.cloudflare.com/mcp`. The documentation server was verified anonymously for tool discovery and a read-only search call on 2026-09-23. The account endpoint uses OAuth and was not accessed as part of that smoke test. For remote servers configured with `--auth oauth`, `pk mcp login ID` performs explicit browser authorization using the official SDK's authorization-code/PKCE flow and persists the resulting session in the private 0600 credential store. `pk mcp status [ID]` reports whether a local session is saved; it does not contact the account server. `pk mcp logout ID` clears the local OAuth session and does not claim to revoke it remotely.

pk does not search a workspace or repository for MCP configuration and does not launch servers found there. The caller passes a trusted server list to `internal/mcpclient.NewHost`. Each entry requires an absolute executable path and may include arguments, explicit environment overrides, and an explicit working directory. With no working directory, the child starts from the user's home directory. The child receives a small baseline environment (`PATH`, `HOME`, temporary-directory variables, and platform essentials) plus the configured overrides; it does not inherit arbitrary process variables such as API keys by default.

Each connected server's tools are discovered during host setup. pk exports a stable, namespaced tool name of the form `mcp_<server-id>_<tool>_<hash>`, sorts the catalog, and omits conflicting exports instead of shadowing built-in tools. The tool input schema and description are bounded before they reach the model. Server tool calls run asynchronously through the harness operation manager and receive the call's cancellation context.

Text result content is returned to the model with a 256 KiB total text limit. Non-text result blocks are reported as unsupported content metadata rather than silently discarded or represented as delivered image data. Calls have a two-minute timeout. MCP connection and discovery are bounded to 20 seconds; explicit interactive OAuth login may wait up to five minutes for the local browser callback. Tool listing is limited to 256 tools per server and 64 KiB per schema. Authenticated remote connection diagnostics suppress server response bodies to avoid reflecting credentials or sensitive server output. Server stderr is not included in model-visible results.

MCP servers execute with the operating-system permissions of pk. Configuration is an explicit trust decision, not a sandbox or permission boundary. Remote URLs require HTTPS, except HTTP loopback endpoints used for development/tests; userinfo, query strings, and fragments are rejected, and redirects are not followed so credentials cannot be sent to another origin. The host does not support prompts/resources, server-side elicitation, dynamic tool-list refresh after initialization, or passing image/audio result blocks through to the model. Shutdown closes stdio children and remote HTTP idle connections.

The official MCP stdio binding specifies newline-delimited JSON-RPC over stdin/stdout, reserves stdout for protocol messages, and defines cancellation through `notifications/cancelled`; see the [stdio specification](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/stdio). The SDK client exposes `Connect`, paginated `Tools`/`ListTools`, and `CallTool`; see its [client documentation](https://github.com/modelcontextprotocol/go-sdk/blob/main/docs/client.md).
