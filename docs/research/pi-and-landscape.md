# Pi and the coding-agent harness landscape

Research checked 2026-09-22. “Better than Pi” needs to mean a measured fit for `pk`’s intended Go, low-overhead workflow; the sources below describe capabilities, not quality rankings.

## Pi: confirm the reference

The likely reference is [badlogic/pi-mono](https://github.com/badlogic/pi-mono), specifically its `@mariozechner/pi-coding-agent` package. The project describes itself as a minimal, aggressively extensible coding agent: features such as MCP, subagents, permission popups, plan mode, and background shell are intentionally left to extensions or the surrounding environment ([coding-agent README](https://github.com/badlogic/pi-mono/blob/main/packages/coding-agent/README.md)). That is a design choice, not evidence of a missing capability by accident.

Pi is layered: provider/model support (`pi-ai`), a reusable agent loop (`pi-agent-core`), and an interactive coding agent (`pi-coding-agent`, with TUI). The [agent loop source](https://github.com/badlogic/pi-mono/blob/main/packages/agent/src/agent-loop.ts) shows a streamed event loop around assistant/tool messages, with tool execution and queued steering/follow-up messages. At the coding-agent layer, built-in tools work over the current directory and can be limited from the CLI; sessions persist as append-oriented JSONL branches, and older context is summarized when needed ([CLI README](https://github.com/badlogic/pi-mono/blob/main/packages/coding-agent/README.md), [session format](https://github.com/badlogic/pi-mono/blob/main/packages/coding-agent/docs/session.md), [compaction](https://github.com/badlogic/pi-mono/blob/main/packages/coding-agent/docs/compaction.md)). It loads `AGENTS.md`/`CLAUDE.md` instruction files from global and ancestor/project locations.

Extensibility is a major strength. TypeScript extensions can register tools and commands, intercept lifecycle/tool events, transform context, adjust compaction, customize UI, and persist extension state. They can be loaded globally, per-project, or packaged for npm/git ([extension API](https://github.com/badlogic/pi-mono/blob/main/packages/coding-agent/docs/extensions.md), [package docs](https://github.com/badlogic/pi-mono/blob/main/packages/coding-agent/docs/packages.md)). Extension code has full process permissions, so this is powerful but not a sandbox.

Practical gaps/opportunities for `pk`, relative to Pi’s stated core: a Go-native integration surface (Go tool plugins/sidecars and typed configs); first-class, consistently enforced tool permissions and filesystem/process boundaries; built-in MCP/subagent/background-task or plan workflows where desired; richer repository-aware context than instruction-file loading and on-demand file tools; and performance/distribution characteristics demonstrated against a workload. Pi can build many of these by extension, so `pk` should compete on integrated defaults and measurable operating cost, not claim Pi cannot do them.

## Nearby open-source designs

| Project | Relevant harness ideas | What it suggests for `pk` |
|---|---|---|
| [Aider](https://github.com/Aider-AI/aider) | Its [repository map](https://github.com/Aider-AI/aider/blob/main/aider/website/docs/repomap.md) extracts important symbols/signatures into a token-budgeted overview; its [modes](https://github.com/Aider-AI/aider/blob/main/aider/website/docs/usage/modes.md) distinguish code and architect workflows. | Explore incremental, budgeted repo maps and explicit inspect/plan/edit modes. Measure context tokens and task success before treating indexing as an advantage. |
| [Continue](https://github.com/continuedev/continue) | Agent tools are model-visible JSON-schema calls; tool execution results are returned to the model. Its documented modes filter tools for read-only plan vs full agent operation, and it supports MCP/configured context ([agent handshake](https://github.com/continuedev/continue/blob/main/docs/ide-extensions/agent/how-it-works.mdx), [plan mode](https://github.com/continuedev/continue/blob/main/docs/ide-extensions/plan/how-it-works.mdx), [config reference](https://github.com/continuedev/continue/blob/main/docs/reference.mdx)). | Make capability and permission policy explicit and inspectable; keep tool schemas/context providers configurable. A read-only policy should constrain execution, not just prompt the model. |
| [OpenHands Software Agent SDK](https://github.com/OpenHands/software-agent-sdk) | A modular SDK separates agent/tools/workspace/server. Its workspace abstraction supports local or remote workspaces; the SDK describes local and ephemeral/containerized workspaces as execution choices ([SDK README](https://github.com/OpenHands/software-agent-sdk), [workspace factory](https://github.com/OpenHands/software-agent-sdk/blob/main/openhands-sdk/openhands/sdk/workspace/workspace.py)). | Treat workspace/execution as an interface so local Go operation can later target isolated or remote workspaces without coupling the loop to a shell implementation. |

## Concrete differentiators worth testing

1. **Lower local cost:** build a Go binary and compare cold start, idle and active RSS, install size, and time to first useful tool result against a pinned Pi release on the same machine. Record OS, commit, model/provider, and cache state; make no “lighter” claim until published measurements reproduce it.
2. **Better task efficiency:** run a small public, fixed set of repository tasks with the same model/provider, prompt, token limits, and starting commits. Report solved tasks, test pass rate, tool calls, input/output tokens, wall time, and cost. Include repeats and failures; do not infer general coding quality from a few tasks.
3. **Safer execution by construction:** test policy cases (read-only task attempts a write; path traversal; destructive shell command; denied tool; timeout/cancel). Measure whether the executor blocks the action, not whether the model usually refrains.
4. **Context value per token:** on the same repositories/tasks, compare plain file search, Aider-style symbol map, and any `pk` index. Record relevant-file recall, prompt tokens, latency, and task completion. Indexing only wins if its measured benefit pays for build/update cost.
5. **Go integration without sacrificing extension speed:** time and count lines of code to add a custom typed tool, context source, and event hook; verify versioning, error propagation, and isolation. Compare against Pi’s TypeScript extension path and Continue’s config/MCP path.

A defensible claim might be: “On workload X and hardware Y, `pk` cold-started in A ms and used B MiB idle RSS versus the pinned Pi version at C ms/D MiB, with equal task pass rate across N runs.” Until such a test exists, “better than Pi” is a product hypothesis, not a result.
