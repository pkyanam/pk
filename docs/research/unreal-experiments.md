# Experiments to build on Unreal

Source reviewed: `unreal-agent` commit [`b7c9bf1`](https://github.com/unreallabsai/unreal-agent/tree/b7c9bf1c5c2fa4127255c07727a7c8413e23944a). These proposals extend existing behavior. Unreal already has per-tool output limits, head/tail truncation with a complete-output path, an allowlisted static tool registry, on-demand skill-body loading, and a prefix/suffix context builder. The experiments below should preserve those contracts.

## 1. Set output limits from a turn-wide context budget

**Current behavior.** Bash accepts `max_output_length`, defaults to 40,000 characters, caps it at 1,000,000, and describes head/tail truncation with a path to full output ([tool schema](https://github.com/unreallabsai/unreal-agent/blob/b7c9bf1c5c2fa4127255c07727a7c8413e23944a/harness/tool/static.go#L39-L56), [limit parser](https://github.com/unreallabsai/unreal-agent/blob/b7c9bf1c5c2fa4127255c07727a7c8413e23944a/harness/tool/output.go#L14-L34)). The shell operation applies this to stdout and stderr separately ([shell result bounds](https://github.com/unreallabsai/unreal-agent/blob/b7c9bf1c5c2fa4127255c07727a7c8413e23944a/harness/operation/shell.go#L447-L448)). `AddToolResult` stages returned content, and `Build` currently copies the entire committed prefix and staged suffix without a context-size policy ([builder](https://github.com/unreallabsai/unreal-agent/blob/b7c9bf1c5c2fa4127255c07727a7c8413e23944a/harness/contextbuilder/builder.go#L103-L136)).

**Experiment.** Compare the existing 40k-character default with lower defaults (for example, 8k and 16k) and a per-turn aggregate output allowance. Keep head/tail markers and complete file paths intact; do not truncate explicit user-requested limits below their value. At context assembly, spend remaining allowance across the new tool outputs and report each omission/truncation through the existing `Report.Changes` type ([report surface](https://github.com/unreallabsai/unreal-agent/blob/b7c9bf1c5c2fa4127255c07727a7c8413e23944a/harness/contextbuilder/contextbuilder.go#L9-L29)). Measure task success, input tokens, redundant rereads, and time to completion. This tests whether smaller routine excerpts reduce cost without hiding useful evidence.

## 2. Implement measured context compaction at the existing turn boundary

**Current behavior.** The builder stores every model response in `committedPrefix`, then appends all staged items on `Commit`; it does not drop or summarize old items ([prefix/suffix lifecycle](https://github.com/unreallabsai/unreal-agent/blob/b7c9bf1c5c2fa4127255c07727a7c8413e23944a/harness/contextbuilder/builder.go#L23-L29), [commit/build](https://github.com/unreallabsai/unreal-agent/blob/b7c9bf1c5c2fa4127255c07727a7c8413e23944a/harness/contextbuilder/builder.go#L88-L136)). `TurnCompaction` and `ChangeCompacted` types exist, and the coordinator recognizes a compaction response and prevents it from being treated as an ordinary action response ([turn types](https://github.com/unreallabsai/unreal-agent/blob/b7c9bf1c5c2fa4127255c07727a7c8413e23944a/harness/session/session.go#L8-L15), [special response handling](https://github.com/unreallabsai/unreal-agent/blob/b7c9bf1c5c2fa4127255c07727a7c8413e23944a/harness/coordinator/loop.go#L453-L475)). The reviewed code does not yet implement a compaction trigger or summary/replacement policy.

**Experiment.** Add a provider-aware input estimator at `Builder.Build`; when estimated input exceeds a soft budget, compact only older committed history, preserving the stable system prompt, recent turns, unresolved tool calls/results, and active task constraints. Rebuild and re-estimate before sending; store the compaction turn and `Report.Changes` so the transition is observable. Compare no compaction with two thresholds on long-session replays. Score constraint/decision retention and task success alongside input tokens, latency, and compaction frequency. Keep session-store history intact so the experiment changes model context, not the audit trail.

## 3. Measure skill catalog cost before adding dynamic tool search

**Current behavior.** Skills are registered by name/path and surfaced as name, description, and location in the system preamble. The preamble explicitly says to use `SkillUse` to load a matching file, while the translator reads that file through an operation ([skill metadata formatting](https://github.com/unreallabsai/unreal-agent/blob/b7c9bf1c5c2fa4127255c07727a7c8413e23944a/harness/contextbuilder/skills.go#L27-L45), [use instruction](https://github.com/unreallabsai/unreal-agent/blob/b7c9bf1c5c2fa4127255c07727a7c8413e23944a/harness/contextbuilder/prompts/skill-preamble.md#L1-L3), [load operation](https://github.com/unreallabsai/unreal-agent/blob/b7c9bf1c5c2fa4127255c07727a7c8413e23944a/harness/tool/skill_use.go#L20-L48)). Static function tools are selected at registry construction and `Resolve` only recognizes the configured static translators ([registry](https://github.com/unreallabsai/unreal-agent/blob/b7c9bf1c5c2fa4127255c07727a7c8413e23944a/harness/tool/registry.go#L39-L79)). Thus skill contents are already progressive, while tool function schemas are not dynamically discovered.

**Experiment.** With current catalogs and a synthetic larger catalog, compare all skill metadata in the preamble against a compact index/search step that reveals a subset before loading full skill content. Separately compare current static schema exposure with deferred schemas only when the tool catalog is large enough to matter. Extend `NewBuilder`/`formatSkillsForPrompt` for skill selection and `Registry.StaticDefinitions`/`Resolve` for deferred tool registration; keep registry resolution allowlisted. Measure discovery misses, tool/skill success, prompt tokens, and added model round trips. Do not add a search round trip for the current three static tools unless it wins this comparison.

## 4. Protect and instrument the reusable prompt prefix

**Current behavior.** `Build` places the system prompt and committed responses before staged inputs; tools are copied into the request separately, while `SetSystemPrompt` rewrites the first committed item ([builder state and prompt](https://github.com/unreallabsai/unreal-agent/blob/b7c9bf1c5c2fa4127255c07727a7c8413e23944a/harness/contextbuilder/builder.go#L23-L40), [system prompt update](https://github.com/unreallabsai/unreal-agent/blob/b7c9bf1c5c2fa4127255c07727a7c8413e23944a/harness/contextbuilder/builder.go#L80-L86), [request build](https://github.com/unreallabsai/unreal-agent/blob/b7c9bf1c5c2fa4127255c07727a7c8413e23944a/harness/contextbuilder/builder.go#L125-L136)). This gives a natural place to preserve stable content, but replacing a system prompt during a session changes the leading prefix.

**Experiment.** Add diagnostics for stable-prefix hash/estimated tokens, tool-schema hash, and provider cache usage when available. Compare current ordering with any proposed skill/tool injection placement; test that ordinary external messages and tool results only extend the suffix. Measure cache-read tokens, input cost, and latency on repeated turns. Treat cache statistics as provider-specific and do not assume a hash proves the provider hit its cache.

## 5. Bound asynchronous work without blocking the coordinator

**Current behavior.** The local operation manager accepts operations into its active map and starts their initial steps; its constructor exposes no concurrency budget. It queues pending updates in a slice ([manager](https://github.com/unreallabsai/unreal-agent/blob/b7c9bf1c5c2fa4127255c07727a7c8413e23944a/harness/operation/local_manager.go#L64-L179)). The inbox similarly has an in-memory pending-input slice ([inbox](https://github.com/unreallabsai/unreal-agent/blob/b7c9bf1c5c2fa4127255c07727a7c8413e23944a/harness/inbox/local.go#L63-L91)). Unbuffered channels alone therefore do not establish a bound on total queued or active work.

**Experiment.** Add admission and process-count limits in a pk manager/host, with explicit queued-operation state and cancellation. Preserve accepted-operation durability and let `Add` return promptly after admission; a semaphore that blocks `Add` until another operation finishes could prevent the coordinator from processing the very results or cancellation needed to make progress. Test many long-running tools, a slow consumer, and cancellation with queued work. Measure peak process-tree RSS, queue depth, throughput, and cancellation latency. This addresses the original hardware-efficiency goal while preserving the asynchronous model.

The first two experiments address direct context spend. Catalog discovery should be gated by catalog size, since the current implementation already has a compact static tool set and progressive skill bodies. Resource admission is a separate host-efficiency experiment; it must not silently turn the async runtime back into a blocking loop.
