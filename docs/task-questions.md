# Durable task questions

Detached tasks can pause for an explicit AskUser response. The worker stores each question in its private task directory before publishing a `task_question` event. The question ID is the runner's stable tool-call ID; a reused ID must have identical session, text, choices, and kind. Each task is limited to 32 questions and the state file is capped at 4 MiB.

Attach clients can seed the question UI from `ListQuestions` (pending questions only), then follow the ordered task event cursor. A `task_question_answer` request carries `task_id`, `question_id`, and `answer`. The store fsyncs the answer before returning success and appends `task_question_answered` with IDs only; answer text is kept in the private question state, not the event stream. Retrying the same answer is idempotent, including after the task finishes. A different answer for an answered question is rejected.

Detaching does not cancel or answer a question. The running worker waits without polling tightly and reuses the stored question when resumed with the same tool-call ID. Explicit task cancellation marks unresolved questions canceled and requests worker cancellation. Cancellation never produces an answer. Once a task is terminal, pending questions are hidden and new answers are rejected.

Question state is the source of truth. On retry, the store checks the event log and repairs a missing question/answer notification if a crash occurred between the atomic state write and event append. The subprocess integration test kills a real task worker while the runner is waiting in AskUser, resumes the same session and tool-call ID, and verifies that the explicit RPC answer reaches the model. This covers persisted questions; it does not guarantee exactly-once external tool side effects after interruption. Notifications are at-least-once: a direct RPC acknowledgement and the task follower may both deliver the same answer event, so clients deduplicate by task and question ID. Existing session snapshots keep their original tool registry; create a new task to acquire AskUser if an older snapshot omitted it.
